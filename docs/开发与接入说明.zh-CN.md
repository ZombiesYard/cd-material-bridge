# CD Material Bridge 0.1.1 — 开发与接入说明

## 功能与边界

CD Material Bridge 是 Windows x64 ASI 插件，为明确匹配的服装 DDS 开启纹理登记中的 Alpha 标志。适用于使用 AlphaTest 的镂空材质；裁切阈值及实际着色仍取决于游戏材质。

插件不生成透明贴图，不修改模型、权重、物理、颜色空间、法线、金属度或粗糙度，也不把不透明 Shader 自动变成渐变半透明 Shader。当前接受传统 128 字节 DDS 头的 BC2 / BC3（DXT3 / DXT5）贴图，不支持 DX10 扩展头。档案中的 DDS 记录必须采用插件支持的直接存储方式。

## 目录与构建

```text
src/
  bridge.cpp                 插件实现
  version.rc                 Windows 版本资源
scripts/
  build_windows.py           独立构建入口
  generate_rule.py           INI 规则生成器
output/
  CDMaterialBridge.asi        编译产物
```

构建需要 Windows x64、Python 3.9 或更新版本、Visual Studio 2022 或其 Build Tools、C++ 桌面开发工具及 Windows SDK。使用静态 MSVC 运行库 `/MT`；链接 Windows 系统库 `bcrypt.lib`。不需要游戏文件、服装资源或 ASI 加载器参与编译。

在仓库目录执行：

```powershell
py scripts/build_windows.py
```

脚本通过 `vswhere.exe` 查找具有 x64 C++ 工具的 Visual Studio，也可直接使用已配置的 x64 Native Tools Command Prompt。非标准安装位置可以指定：

```powershell
py scripts/build_windows.py --vcvars64 "C:\Tools\VisualStudio\VC\Auxiliary\Build\vcvars64.bat"
```

入口由脚本位置确定，运行时的工作目录不影响源码定位。构建使用 C++17、`/O2 /W4 /WX /MT`、`/DYNAMICBASE /NXCOMPAT /Brepro`。中间文件和日志写入 `build/`，成功后才更新 `output/CDMaterialBridge.asi` 并打印 SHA256。它不会打包、安装或加载插件。不同编译器、选项和版本资源可能产生不同二进制哈希。

## 初始化与文件处理

`DllMain` 仅保存模块句柄并关闭线程通知；加载器通过导出的 `InitializeASI` 触发一次初始化。插件检查进程文件名为 `CrimsonDesert.exe`，并查找 Ultimate ASI Loader 的 `IsUltimateASILoader`、`AddVirtualPathForOverloadW`、`RemoveVirtualPathFromOverloadW` 接口。

1. 读取 ASI 同目录下 `CDMaterialBridge/rules/*.ini`，最多 256 个文件、1024 条规则。
2. 读取游戏根目录的 `meta/0.papgt`，按登记顺序检查各组 `0.pamt`；路径第一次命中后，只验证该生效资源，不继续寻找低优先级的旧版本。
3. 读取对应 PAZ 内的 DDS，核对路径、尺寸、mip 数、FourCC 和完整压缩像素数据的 SHA256。
4. 从 `meta/0.pathc` 查找匹配登记，核对 DDS 头和 `BaseFlags`。仅设置头内偏移 124 的标志最低位，即 `flags |= 1`。
5. 若该头被多个登记共用，复制头并仅重定向目标登记；保留其他标志、记录和 mip 块信息。
6. 重新读取 PATHC 和 PAPGT，确认初始化期间挂载未变。将修正表写入插件缓存，校验后通过加载器注册文件路径重定向，并再次读取确认。

原始 PATHC、PAPGT、PAMT、PAZ 和游戏可执行文件不会被覆盖。缓存与日志会写入磁盘。重定向优先级为 0；加载器拒绝冲突重定向时，插件会记录错误。注册后的读取回验失败会撤销本次重定向。

## PATHC 处理

当前解析布局为 28 字节表头、148 字节 DDS 头数组、路径校验值数组、20 字节直接记录、24 字节碰撞记录及名称区。路径查找使用带游戏种子的 Jenkins lookup3；碰撞记录再按完整路径确认。与目标无关的既有碰撞范围保持原样，目标范围无效则跳过。0.1.1 允许 PAMT 目录表中的空根目录；纹理规则仍必须使用非空的合法相对路径。

## 为纹理生成规则

先准备正确的游戏材质和 BC2 / BC3 Alpha 贴图，再从最终生效的挂载资源提取 DDS。若管理器改变分辨率或编码，应以处理后的文件生成规则。

```powershell
py scripts/generate_rule.py mounted-lace.dds --texture character/texture/example/lace.dds --name ExampleLace --base-flags 4 --output ExampleLace.ini
```

这里的 `4` 仅为示例，必须替换成目标 PATHC 登记的实际标志清除最低位后的值。

| 字段 | 要求 |
| --- | --- |
| `[Texture:名称]` | 每条规则的节名 |
| `Enabled` | `0` 停用；生成器输出 `1` |
| `Path` | `character/texture/` 下以 `.dds` 结尾的虚拟路径 |
| `Width` / `Height` | 1–16384，与 DDS 和登记一致 |
| `Mips` | 1–15，与 DDS 和登记一致 |
| `FourCC` | `DXT3` 或 `DXT5` |
| `BaseFlags` | 预期原标志，Alpha 最低位必须清零 |
| `PixelSHA256` | DDS 第 128 字节之后全部数据的 SHA256，覆盖所有 mip |

将 INI 放入 `CDMaterialBridge/rules/` 并保留其他服装使用的规则。运行插件不需要 Python。同一路径可以有不同像素版本的规则，但只能匹配实际生效的版本。更新、缩放或重新编码贴图后应重新生成规则，不应取消哈希检查。

## 运行文件与兼容性

- 日志：`bin64/CDMaterialBridge/CDMaterialBridge.log`。
- 缓存：`bin64/CDMaterialBridge/cache/<SHA256>.pathc`，哈希来自完整修正表。
- 通常将 ASI 放在 `bin64`；规则和缓存目录始终相对于实际 ASI 位置。
- 规则在初始化时加载；更新规则、挂载或停用插件后应完全重启游戏。
- 运行中不得重新挂载资源。初始化时的读回检查不能保证运行期间任意挂载都安全。
- 其他插件对同一 PATHC 的重定向可能冲突。格式或加载器 API 变化需要更新实现。
